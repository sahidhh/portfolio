Profile Router: pick the model before the model gets to think

An extension for OMP, the coding-agent CLI I use daily, that classifies every prompt with plain keyword scoring — no LLM in the loop — then sets model, thinking level, tools and rules for that one turn.

Role Solo — design, code, tests, docs
Stack TypeScript, Node built-ins only
Size 1 source file + 1 JSON table
SourceDecision log

Why I built it

In early July 2026 I spent a week designing something I called an Engineering Knowledge Compiler: a vendor-neutral library of engineering profiles, model tiers and escalation rules, plus a six-pass compiler to turn them into config for any AI coding agent. Fourteen spec files, about 300 KB of markdown. No code.

Then I asked, twice, whether it needed to exist next to what already shipped. Honest answer: the only piece I would use every day was the routing table — which model, which tools, for which kind of prompt. Everything else was me enjoying architecture.

So I salvaged the profile definitions and the keyword table out of the specs and wrote the smallest thing that would run: one TypeScript file, one JSON table, no dependencies. First commit July 10, working extension July 11. A week later I formally killed the vendor-neutral charter in the decision log — it had stopped earning its complexity.

The problem

Route each prompt to a cheap model when it's safe and a strong one when it matters — without spending an LLM call to decide, which would eat the savings, and without ever routing a destructive action to the cheap tier.

How it works

flowchart LR
  P[prompt] --> C[classify\nword-boundary keyword scores\nno LLM]
  C --> M[merge matched profiles]
  M --> R[rules → system prompt\nthis turn only]
  M --> MD[model chain\ncheap primary → fallback]
  M --> T[thinking level]
  M --> TL[toolset restricted 🔒]
  M --> A[disabled subagents blocked]

Seven profiles live in bundles.json: lookup, hotfix, investigation, implementation, architecture, review, premium. Each has trigger keywords, a model chain, a thinking level and an allowed toolset. When several match, rules and tools union; disabled subagents intersect (safety-conservative); model and thinking go to the highest score.

Decisions that mattered

  • Keyword scoring, not an LLM classifier. Routing that costs tokens defeats the purpose. Word-boundary matching plus per-keyword weights got within acceptable accuracy for free.
  • premium has a minimum score of 2. Early versions sent every prompt containing "schema" or "secret" to the expensive tier. A bare noun now needs a second signal; single destructive verbs (force-push, reset --hard) are weight 2 on their own.
  • Downgrades apply silently, upgrades confirm once. Nobody wants a dialog to use the cheap model. Going up costs money, so it asks — once per (from→to) pair, persisted across sessions.
  • Fallback chains, and premium has none. Cheap tiers chain through providers until one has credentials. The safety tier deliberately cannot fall down to a cheaper model.
  • Tests that guard the table, not just the code. A reachability test proves every profile's trigger prompt reaches that profile; a regression test fails the build if adding a keyword lets another profile outrank it.
